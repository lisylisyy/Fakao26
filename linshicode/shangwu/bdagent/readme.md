# bdagent — 淋浪商务 Agent（飞书机器人）

独立子项目：飞书长连接商务机器人（agent 本体，根目录）+ 模拟对话训练台（`bot/` 目录）。
两者是**两个独立常驻进程**，需要分别启动、各占一个终端窗口。

角色模型（三方）：群里有**客户**、**运营**（真人，公司主要人员）和 **bdagent**（辅助运营的机器人）。
bdagent 旁听对话，检测到新客户就主动发登记表单，被 @/点名才接话；客户问到**商务语料库**
覆盖的常见问题（合作模式/报价/入库流程等）时即使没被点名也会按语料口径主动解答，其余时间沉默记录。
训练台的 `bot/kehu`、`bot/yunying` 分别用 LLM 扮演客户和运营真人，bdagent 跑的是真实决策代码。

**商务语料库**：[商务Agent语料库.md](商务Agent语料库.md)（倩逸维护）是机器人回答业务问题的唯一
权威口径。**直接改这个文件即热生效**（不用改代码、不用重启），机器人回答时数字/条款严格按语料，
语料没有的不编造。录入完成后机器人会按语料 SOP 发拉会话术并 @季倩逸 确认时间
（@对象可用 `.env` 的 `MEETING_CONFIRMER_NAME` 改，留空关闭）。

> ⚠️ 生产群目前只开通了"接收 @机器人 的消息"权限，所以生产环境里客户**不@机器人**直接提问
> 暂时触发不了 FAQ 自动应答（@它问是可以的）。要完整生效需去飞书开放平台给应用申请
> 「**接收群聊中所有消息**」权限；训练台旁听模式不受影响，已可完整测试。

## 启动前提

- 依赖已装在项目自带的虚拟环境 `.venv` 里（Python 3.11），无需激活，直接用完整路径调用即可
- `.env` 已配置好全部密钥（飞书 App ID/Secret、DeepSeek Key、两个webhook、测试群 chat_id），**不要提交到 git**
- 若换了新机器：`python -m venv .venv` 后 `.venv\Scripts\pip install -r requirements.txt`，再把 `.env.example` 复制为 `.env` 填入真实值

## 1. 启动商务 agent（真实飞书机器人）

```powershell
cd E:\linlang\LinlangAgent\shangwu\bdagent
.\.venv\Scripts\python.exe main.py
```

- 无界面，日志出现 `connected to wss://msg-frontier.feishu.cn...` 即连接成功
- 长连接模式，不需要公网域名
- 之后在飞书群里 @淋浪商务机器人 发消息即可触发（群聊必须@它，私聊不用）
- 停止：Ctrl+C 或直接关窗口

## 2. 启动训练台（模拟对话控制台）

```powershell
cd E:\linlang\LinlangAgent\shangwu\bdagent
.\.venv\Scripts\python.exe bot\server.py
```

启动前先确认 8899 端口没被旧进程占用（占着的话 uvicorn 只打一行 ERROR，进程看起来却像在跑，
请求全打到旧代码上，现象非常诡异）：

```powershell
Get-NetTCPConnection -LocalPort 8899 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

- 启动后浏览器打开 **http://127.0.0.1:8899**
- 三栏界面：左=会话列表（新建/结束会话），中=扮演角色（客户/运营），右=聊天区
- 机器人（bdagent）不用扮演：它自动旁听每条消息，自己决定弹卡、接话或沉默（紫色气泡）
- 右上角"开始自动聊天"= 客户和运营两个人设自动轮流对话（20轮安全上限，随时可停）
- 模拟对话会同步显示在飞书测试群里；模拟数据带 `is_simulated=1` 标记，不会混入真实客户数据
- 停止：Ctrl+C 或直接关窗口

## 3. 启动管理后台（生产群管理）

```powershell
cd E:\linlang\LinlangAgent\shangwu\bdagent
.\.venv\Scripts\python.exe admin\server.py
```

- 浏览器打开 **http://127.0.0.1:8898**（启动前确认 8898 端口没被旧进程占用，方法同上）
- 仿飞书三栏：左=机器人所在的群，中=聊天记录（机器人听到并记录的消息），右=该群设置+成员角色
- **每群可配（改完立即生效，机器人不用重启）**：
  - 启用机器人：关=只记录消息，回复/弹卡/安抚全停
  - 消息收集模式：主动问询（检测到新客户弹登记表单）/ 默默收集（只记录）
  - 被@时回复 开关
  - 秒答常见问题：没被@也按语料库直接回答FAQ（默认关）
  - 无人回复安抚：客户消息超过 X小时Y分钟 没有任何"标了角色的员工"回复 → 群里发
    "XXX 正在飞快赶来"+语料能答的顺带答+**私信提醒对应同事**（注明哪个群哪条消息）。默认关
- **淋浪人员名册（全局，配一次所有群通用）**：右栏名册区，或直接在"本群成员"里给某人选职务=把他
  加进名册（自家人）。群成员命中名册=淋浪自家人+职务，其余=客户。喂 LLM 的历史标签是
  "淋浪+职务+姓名"（如"淋浪商务对接运营季倩逸"）。无人回复时按客户问题类型（LLM分类）提醒对应
  职务的人。**按姓名匹配，首次在成员面板选职务时钉住 open_id 防重名**。
- **身份读取时按当前名册现算（不冻结）**：改名册后所有群的历史身份和颜色**立刻跟着变，不用重取**。
- **⟳ 同步历史（每群右上角）/ 启动自动追赶**：从飞书 `im/v1/messages` 拉群历史入库，按 message_id
  去重（实时推送+历史拉取不重复）。每群一个游标（`chat_sync_state`）断点续传；机器人启动时自动
  补掉线期间错过的消息。历史消息按真实发送时间排序/显示。
- ⚠️ 完整生效依赖「接收群聊中所有消息」权限（`im:message.group_msg`，已开通）。同步历史需要该读权限。

## 注意事项

- 两个进程互不依赖，可以只开其中一个；但训练台里 bdagent 用真实身份发卡/发言，需要 `.env` 里 `TEST_GROUP_CHAT_ID` 已配置（当前已配置为测试群；留空则退回打桩+webhook兜底，不碰真实API）
- 数据库文件在 `data/bdagent.sqlite3`（gitignore 保护，含真实客户数据不要提交）
- 一定要用项目自带的 `.venv\Scripts\python.exe` 启动，不要用系统 Python（依赖不在系统环境里）
- 飞书云文档权限已开通（wiki 读 + bitable 读写），多维表格《商务agent》已授权可编辑，详见 dev-log
- **录入客户会自动同步写多维表格《商务agent》**（`bitable.py`，后台线程，仅真实录入；训练台模拟数据不写）。
  同步失败不影响录入，本地 clients 表里 `is_simulated=0` 且 `bitable_record_id` 为空的行即漏同步记录，可事后补写。
  表格换了的话改 `.env` 里 `BITABLE_WIKI_TOKEN`（wiki 节点 token，非 app_token）和 `BITABLE_TABLE_ID`；留空则关闭同步
- 开发交接记录见 [dev-log.md](dev-log.md)（新会话交接入口在文末"六、交接给新会话"）
